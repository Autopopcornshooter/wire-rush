# 구현 결정 — 0.7.0

사용자 피드백에 따라 일반 스윙은 수동 한 줄을 유지하고, 양쪽 벽이 자주 비는 건물 간격 배치에서 의미가 약해진 E 두 줄 사출을 제거했습니다. 대신 공중에서 쓰는 벽 점프·이중 점프를 새 기본 이동 능력으로 추가했습니다. 이어서 스케이트를 마찰 감속 방식에서 등급별 지속시간 방식으로 되돌리고, 점프 높이와 이중 점프를 별개의 업그레이드로 분리했으며, 레벨업을 즉시 정지시키지 않고 대기 스택에 쌓아 G 키로 원하는 타이밍에 모두 소비하도록 바꿨습니다. 최초 기획 원문은 `ORIGINAL_BRIEF.md`, 과거 구현은 Git 태그에 보존합니다.

## 사거리 보정과 연결된 장애물

카메라 광선이 맞힌 연결 가능 표면이 사거리 밖이면 플레이어→조준점 방향의 최대 사거리 위치를 기준으로 대체 표면을 탐색합니다. 현재 도시의 축 정렬 박스 충돌체 각 면을 사거리 구와 겹치는 영역으로 제한합니다. 면 안의 가까운 점에서 조준점 투영점까지 이분 탐색하여 사거리 경계 후보를 만들고, 최대 사거리 위치에 가까운 순서로 실제 광선 가림·최소 높이를 검사합니다. 사거리 경계에는 0.001m 여유를 둡니다.

선택한 표면 위에만 앵커를 생성합니다. 작은 장애물이나 건물 사이 틈 때문에 정확히 최대 거리에 표면이 없으면 더 가까운 유효 표면을 사용합니다. 유효 표면이 없거나 바닥·하늘을 조준하면 연결하지 않습니다. 미리보기에는 보정 사유와 실제 연결점을 표시하고, 발사 시 같은 점을 다시 검증합니다. 회전하거나 박스가 아닌 지형을 추가하면 면 후보 생성도 확장해야 합니다.

연결이 완료된 공중 장애물의 RID만 와이어 경로 광선에서 제외합니다. 장애물 뒤로 스윙할 때 연결된 블록 자체가 가림으로 오인되던 문제를 수정했습니다. 갈고리 비행 중·다른 물체의 가림·캐릭터 충돌 검사는 유지합니다. 건물은 이 제외 규칙을 적용하지 않습니다.

## 착지 이력

`release_wire()`가 실제 연결된 줄을 해제할 때 플레이어의 `global_position.y`를 `last_release_height`에 기록합니다. 단위는 도로 y=0 기준 m이며 플레이어 원점(캡슐 중심)을 사용합니다. 연결 성립 자체·앵커 높이·해제 후 이동은 기록을 바꾸지 않습니다. 재발사 실패·비행 중 갈고리 취소·이미 해제된 줄 정리도 기록을 유지합니다. 부동소수점 경계 오차 0.00001m만 허용합니다.

줄 교체·가림·복귀의 실제 해제도 같은 함수를 사용합니다. 줄을 계속 잡은 채 도로에 닿으면 접촉 높이에서 자동 해제한 뒤 판정합니다. HUD의 `landing_height()`는 연결 중에만 현재 플레이어 높이로 해제 결과를 미리 보여주고, 이후 저장된 해제 높이를 보여줍니다.

도로는 `road` 메타데이터를 가진 충돌체입니다. 도로의 위쪽 면에 닿을 때 마지막 해제 당시 플레이어 높이가 5m를 넘으면 `die`로 직접 종료하므로 방어구·복귀 보호·연습 복구로 우회하지 않습니다. 건물·공중 장애물 접촉은 별도 장애물 충돌입니다.

일반 점프에는 높이 예외를 부여하고, 새로운 연결이 실제로 성립하면 예외를 해제합니다. 스케이트를 시작할 수 있는 새 연결 표시는 착지 시 소모합니다. 점프 자체가 이 표시를 재충전하지 않습니다. 최초 연결 전의 시작 낙하는 정지로 처리합니다.

## 스케이트

60Hz 물리 프레임 안에서 2회 서브스텝을 사용합니다. 지상 스케이트는 감속하지 않는 시간제 슬라이드입니다. 착지 순간 `land()`가 `slide_left = Rules.SLIDE_SECONDS[tiers.skates]`(2/3/4초)를 설정하고, `integrate()`는 매 서브스텝 `slide_left -= dt`만 수행합니다. 속력은 유지한 채 조향만 진행 방향 벡터를 회전시키며(`horizontal.normalized().rotated(...)`), 새 속력을 만들어내지 않습니다. `slide_left`가 0 이하가 되는 순간 `stop_on_ground()`로 즉시 정지합니다.

와이어의 예상 위치 제약과 충돌 sweep을 유지합니다. 마지막 줄 해제 자체는 속도를 바꾸지 않습니다. 자동 앵커 네트워크·마우스 두 줄 독립 모드·E 두 줄 사출은 계속 제외합니다.

## 건물과 장애물

건물 충돌체의 원점을 지면에 고정하고 메시·콜라이더의 중심과 높이를 바꿉니다. 벽에 부착한 임시 연결점은 이동하지 않습니다. 기본 높이 23~35m, 업그레이드 추가 높이 10/20/30m. 이미 생성된 청크와 미래 청크에 동일하게 적용합니다.

첫 128m 이후 도전 청크에는 14m 간격의 작은 공중 블록 4개가 있습니다. 크기 2.6×2.2×1.4m, x=-3.7/0/3.7m, y=6/12/18/24m를 순환합니다. 높이 업그레이드는 블록을 +8/+16/+24m 이동시킵니다. 연습 모드에는 이 소형 공중 장애물을 생성하지 않습니다.

공중 장애물은 `hazard`와 `hookable`을 동시에 가집니다. 표면 조준의 사거리·최소 2.5m 높이·줄 경로 가림 검사를 그대로 적용합니다. 연결점은 맞힌 충돌체의 자식이며, 장애물이 높아지면 연결점도 따라갑니다. 착지 이력은 앵커 움직임과 무관하게 플레이어의 해제 높이를 사용합니다. 연결 중인 청크는 정리에서 보호합니다.

## 벽 점프와 이중 점프

`Rider.touching_wall_side`는 물리 서브스텝의 충돌 sweep에서 갱신합니다. `mode == "air"`이고 충돌 법선이 대체로 수평(`|normal.y| < 0.4`)이며 상대가 `building` 메타를 가지면, 법선의 x 부호를 저장합니다. `simulate()`가 매 프레임 시작에 이 값을 0으로 리셋하므로 항상 직전 서브스텝의 실제 접촉만 반영합니다. `jump()`는 지상/슬라이드 점프를 먼저 확인하고, 그다음 `touching_wall_side != 0`이면 벽 점프(저장된 부호 방향으로 `Rules.WALL_JUMP_PUSH`만큼 수평 속도, 기존 점프와 동일한 수직 속도)를 수행하며, 마지막으로 공중에서 이중 점프 조건을 확인합니다. 벽 점프는 이중 점프의 재사용 대기와 무관하게 항상 사용할 수 있습니다.

`integrate()`의 충돌 분기 `elif not collider.get_meta("road", false) and (invincible > 0 or impact > 3): hurt(...)`는 원래 건물에도 그대로 적용되어, 실제 게임 속도(10~35m/s)에서는 건물 벽에 스치기만 해도 `impact`(법선 방향 속도 성분)가 3m/s를 거의 항상 넘어 `touching_wall_side`가 설정되기 전에 `hurt("OBSTACLE COLLISION")`이 먼저 발동했습니다. 그 결과 벽 점프가 코드상 존재해도 실전에서 발동 조건에 도달하지 못했습니다. 조건에 `not collider.get_meta("building", false)`를 추가해 건물은 몸으로 부딪혀도 항상 안전하게 미끄러지도록(그 과정에서 `touching_wall_side` 설정) 바꾸고, 공중 장애물(`hazard`)만 기존처럼 위험하게 유지했습니다.

**벽 점프 자체는 현재 비활성화 상태입니다.** `jump()`의 벽 점프 분기(`elif mode == "air" and touching_wall_side != 0: ...`)를 주석 처리해 실행되지 않도록 했습니다. 위 안전 충돌 수정은 유효하므로 `touching_wall_side`는 계속 정상적으로 갱신되지만, 실제로 점프를 유발하지는 않습니다. 재활성화하려면 해당 주석을 해제하면 됩니다.

## HUD 정리

메뉴의 부제목·조작 요약·오른쪽 안내 패널, 플레이 화면 상단 중앙의 능력 제목·이중 점프 상태, 커서 옆 조준 설명 텍스트, 착지 높이·위험 표시, 하단 알림 배너, 일시정지/결과 화면의 문구를 정리했습니다. 진행 거리·최고 기록·속도·스케이트/방어구/건물/슬라이드 요약을 좌상단 한 패널로 합쳤고, 조작 안내는 좌하단의 작은 패널로 옮겼습니다. 레벨 표시는 화면 하단 전체 폭 XP 바로 위, 그 바로 왼쪽에 배치합니다. 조준 십자선·사거리 보정 표식·연결점 표시는 유지해 핵심 조준 피드백은 남겨두었습니다.

**점프 높이와 이중 점프는 서로 다른 업그레이드**(`tiers.jump`, `tiers.double_jump`)입니다. 모든 점프(지상·벽·이중)의 수직 속도는 `Rules.JUMP_SPEED * sqrt(1 + tiers.jump * 0.1)`로 `tiers.jump`에만 의존합니다. 이중 점프의 재사용 대기 `double_jump_left`는 순수 쿨다운으로만 동작합니다: `mode == "air"`에서 `double_jump_left <= 0`이면 발동하고 `Rules.DOUBLE_JUMP_COOLDOWN[tiers.double_jump]`(10/7/5/3초)를 다시 채우며, 매 서브스텝 `dt`만큼 감소합니다. 착지 여부와 무관하게 오직 이 타이머만으로 재사용 시점을 결정하므로 landing에서 별도로 리셋하지 않습니다.

E 두 줄 사출과 관련 퍽(`launcher`)·설정(`preferences.route`, 배치 선택 UI)은 모두 제거했습니다.

## 건물 배치

`City.has_building()`은 이제 연습 모드에서 항상 `true`를 반환해 양쪽 벽을 유지합니다. 비연습 모드는 과거 실험 배치 중 건물 간격 방식을 기본값으로 고정해, 첫 128m 이후 128m 구역마다 건물이 있는 쪽이 번갈아 바뀝니다(구역 첫 16m는 양쪽 벽이 겹치는 전환 구간). 다른 배치 실험(기존 배치·수직 차단벽)과 배치 선택 저장값은 제거했습니다.

## 업그레이드 대기와 G 키

`_physics_process`는 더 이상 XP 임계값에 도달한 즉시 선택 화면을 열지 않습니다. 매 프레임 `while xp >= Rules.xp_required(level): xp -= ...; level += 1; pending_upgrades += 1`로 레벨과 대기 개수만 누적하고 플레이는 계속됩니다. `phase == "playing"`에서 `pending_upgrades > 0`일 때 G 키를 누르면 `open_upgrades()`가 호출되어 그 순간 처음으로 물리·재사용 타이머를 정지시킵니다.

`open_upgrades()`가 구성한 후보 풀이 비어 있지 않으면(선택 가능한 능력이 남아 있으면) `phase = "upgrade"`로 전환하고, 첫 업그레이드는 `upgrades_taken == 0`일 때만 스케이트를 보장합니다(레벨이 아니라 실제로 받은 업그레이드 개수를 기준으로 판단). 후보 풀이 비어 있으면(모든 능력이 최대이고 방어구도 충전되어 있으면) 대기 하나를 조용히 소비하고 즉시 자기 자신을 재귀 호출해 다음 대기를 확인하므로, 이미 맥스인 상태에서 레벨업을 여러 번 쌓아도 빈 모달이 뜨지 않습니다.

`choose(index)`는 이제 XP·레벨 계산을 하지 않고 `rider.upgrade(...)`만 적용한 뒤 `pending_upgrades`를 1 줄입니다. 아직 대기가 남아 있으면 `open_upgrades()`를 다시 호출해 곧바로 다음 선택지를 보여주고(화면이 끊기지 않고 이어짐), 없으면 기존과 같이 `resume()`으로 카운트다운을 시작합니다.

## 남은 검증

자동 검사는 위치·속도 fixture와 실제 충돌 이동을 함께 사용합니다. 연속 주행 검사는 벽에 수동 위치를 지정하는 자동 입력으로 장애물 없는 연습 구간을 이동합니다. 사람의 자유 조작, 모든 장애물 조합, 상층 경로의 공정성까지 검증했다는 의미는 아닙니다. 카메라는 이전 먼 설정을 유지합니다.
